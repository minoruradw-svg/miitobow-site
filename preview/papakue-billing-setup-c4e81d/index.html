課金（月490円・初回1か月無料）の用意 手順書

アプリ内の購入（サブスク）を動かすための、あなたの作業です。コードの用意と、サーバー（購入の通知を受ける窓口）は、もう済んでいます。
A → B → C の順に、上から押すだけです。所要時間は約1〜1.5時間（Aの「契約」は、Appleの確認で、数日かかることがあります）。

⚠ 秘密の値は、チャット・メール・スクリーンショットに載せないでください：
・RevenueCat に入れる「合言葉」（下の手順B5のファイルの中身）
・App Store Connect の「アプリ内課金のキー（.p8）」
画面に直接入れるだけにして、私（Claude）にも、値は見せないでください。

先に知っておくこと

  • 商品の名前（ID）は、これで固定：papakue_pro_monthly（コードがこの名前を前提にしています。1文字でも違うと、購入画面に出ません）。
  • サブスクのグループは1つ・商品は1つ。無料トライアルは、この1つにだけ付けます。「戻ってきた人向けの無料（ウィンバック）」は、設定しないでください（無料の抜け穴になるため）。
  • 開発用ビルドでの購入は、自動でテスト（Sandbox）になり、お金は、かかりません。
  • RevenueCat は、月の売上が約2,500ドルを超えるまで無料です（登録時に、料金の最新の条件を、一度見てください）。

A．App Store Connect（Apple）

A1

「有料App契約」を有効にする（最優先）

約20分＋Appleの確認待ち
  1. appstoreconnect.apple.com にサインインし、ビジネス（または「契約、税金、銀行口座」）を開く。
  2. 有料App（Paid Apps）の契約の行で、契約を確認 → 同意する。
  3. 同じ画面で、銀行口座と税務情報を入れる（画面の案内どおり）。
  4. 状態が 有効 になれば完了。「処理中」の間は、待つだけで大丈夫です（数日かかることがあります）。
すでに「有効」なら、何もせず次へ。ここが有効でないと、商品が、購入テストでも出てこないことがあります。
A2

サブスクのグループと商品を作る

約15分
  1. App Store Connect の アプリ → パパクエ を開く。
  2. 左のメニューの 収益化 → サブスクリプション（Monetization → Subscriptions）を押す。
  3. グループを作成。参照名＝パパクエ プロ。
  4. グループの中で サブスクリプションを作成：
    ・参照名＝パパクエ プロ（月額）
    ・製品ID＝papakue_pro_monthly（あとで変更できません。コピーして貼ってください）
  5. サブスクリプション期間＝1か月。
  6. サブスクリプション価格の価格を追加で、日本・490円を選ぶ（ほかの国は、自動で換算されます）。
  7. ローカリゼーション（日本語）：
    ・表示名＝パパクエ プロ
    ・説明＝おねがいを送り放題・広告なし（短くてOK）
A3

「初回1か月無料」を付ける

約5分
  1. さっきの商品の画面で、サブスクリプション価格の近くにある導入オファー（Introductory Offers）を押す。
  2. オファーを作成 → 種類＝無料、期間＝1か月（画面で「1か月」が選べることを確認）、対象の国＝すべて、開始日＝今日、終了日＝なし。
  3. 「プロモーションオファー」「オファーコード」「ウィンバックオファー」は、作らないでください。
「1か月」が選べない場合は、選べる期間を、私に教えてください（アプリの文言を合わせます）。
A4

アプリ内課金のキー（.p8）を作る（RevenueCat用）

約5分
  1. App Store Connect の ユーザとアクセス → 統合（Integrations）→ アプリ内課金（In-App Purchase）を押す。
  2. キーを生成（または＋）。名前は、papakuebilling（半角英数字だけ）。
  3. .p8 をダウンロードする（ダウンロードは、一度だけです。Mac・パソコンの、わかる場所に保存）。
  4. 画面の キーID と、上に出ている 発行者ID（Issuer ID） を、メモ帳などに控える（B-2で使います）。
⚠ この .p8 は、通知用の .p8（papakuepush）とは、別のものです。混ぜないでください。
A5

テスト用のApple ID（Sandbox）を作る

約5分
  1. App Store Connect の ユーザとアクセス → Sandbox → テスター（Test Accounts）→ ＋。
  2. 名前・メールアドレス・パスワード・国（日本）を入れる。メールは、実際に使っていない、新しいもの（例：自分のアドレスの「＋」付き ○○+test1@gmail.com でも可。本物のApple IDは、使えません）。
  3. iPhoneで、設定 → デベロッパ → Sandbox Apple アカウント にサインインする（「デベロッパ」の項目は、Xcodeでアプリを入れたことがあるiPhoneに出ます）。
A6

（任意・おすすめ）小規模事業者プログラムに登録

約5分
  1. App Store Small Business Program のページから、申し込む。
  2. 承認されると、Appleの手数料が30% → 15%になります（年間の売上が100万ドルまでの開発者が対象）。

B．RevenueCat

B1

アカウントとプロジェクトを作る

約5分
  1. app.revenuecat.com で、アカウントを作る（無料）。
  2. Create new project → 名前＝パパクエ。
B2

アプリ（iOS）を足して、Appleと連携する

約10分
  1. プロジェクトで Apps（または「+ New」）→ App Store を選ぶ。
  2. App name＝パパクエ、Bundle ID＝com.miitobow.todoQuest。
  3. In-app purchase key の欄に、A4の .p8 をアップロードし、キーIDと発行者IDを入れる。
  4. 保存する。「接続できた」などの表示が出れば成功。
B3

商品・権利・オファリングを作る

約10分
  1. Product catalog → Products → 商品を足す（Importで、App Store Connect から取り込めます）。製品ID＝papakue_pro_monthly。
  2. Entitlements → New：識別子＝pro（小文字で pro。コードがこの名前を見ています）。作ったあと、この権利に商品 papakue_pro_monthly を紐づける。
  3. Offerings → New：識別子＝default。中にPackageを足し、種類＝Monthly（月額）、商品＝papakue_pro_monthly。
  4. この default を、「現在（Current）」のオファリングにする（最初の1つは、自動でなります。違っていたら切り替える）。
B4

「公開SDKキー」を控える

約2分
  1. Project settings → API keys を押す。
  2. iOSアプリ用の Public app-specific API key（appl_ から始まる文字列）を、コピーする。「Secret」と書かれたキーでは、ありません。
  3. あとで、C-1で、Macのファイルに、貼ります（チャットには、貼らない）。
B5

Webhook（購入の通知）を登録する

約5分
  1. Integrations → Webhooks → Add new webhook（または「+ New」）。
  2. Webhook URL（このまま貼る）： 
    https://asia-northeast1-papakue-dev.cloudfunctions.net/revenueCatWebhook
  3. Authorization header value（合言葉）：パソコンの、次のファイルをメモ帳で開き、中身の1行を、まるごとコピーして貼る。 
    P:\work\apps\todo-quest\firebase\.secrets\revenuecat-webhook-auth.txt
    （Macで作業する時は、このファイルの中身を、私が別の方法で、渡します。教えてください。）
  4. Environment＝Production and Sandbox（両方）。Events＝すべて。App＝パパクエ。
  5. 保存して、Send test event（テスト送信）を押す。成功（200）と出れば、OK。
うまくいかない時（401などの失敗）は、失敗の表示を、私に教えてください（合言葉の値は、見せなくてOK）。

C．アプリにキーを渡して、試す

C1

MacBookに、公開SDKキーを置く

約3分

MacBookの「ターミナル」で、次を1行ずつ実行します。ここにキーの部分だけ、B4でコピーしたキー（appl_…）に置き換えてください（この1行を、チャットには、貼らないでください）。

echo 'ここにキー' > ~/.todoquest-revenuecat-ios-key

この1行は、キーを、Macのホームフォルダの隠しファイルに保存するだけです（Gitには、入りません）。

C2

アプリを更新して、購入を試す

約10分
  1. いつものコマンドで更新： 
    cd ~/Developer/todo-quest && git pull --autostash && sh tool/mac_run.sh
  2. iPhoneで、Sandboxのテスト用Apple IDにサインインしておく（A5）。
  3. アプリのパーティ画面で、「プランを見る」から購入画面を開く。価格・「初回1か月無料」が出ているか、見る。
  4. 購入する（Sandboxなので、お金は、かかりません。Sandboxでは、1か月が、数分に縮みます）。
  5. 購入のあと、「反映中…」を経て、有料の表示になることを確認する。
⚠ 購入を試すアプリのアカウントは、奥さまや、あなたの普段のアカウントではなく、できれば、試験用のもので。理由：Sandboxの購入が期限切れになると、そのアカウントの「有料の印」が、外れます（普段の、手動の印を使っているアカウントで、試すと、印が消えます。その時は、私が付け直します）。

うまくいかない時（先に、よくある原因）

  • 購入画面が「準備中」のまま：C1のキーが入っていない／アプリを、sh tool/mac_run.sh 以外で起動した。
  • 価格が出ない・商品が見つからない：A1の契約が「有効」でない／商品IDの綴りの違い／B3でオファリングが「現在」でない。
  • 購入できたのに、有料にならない：B5のWebhookが、失敗している（RevenueCatの Webhooks の履歴を見る）。表示を、私に教えてください。

公開する前に（今は、やらなくて大丈夫）

  • 本番用の Firebase プロジェクトを作ったら、Webhookの関数と合言葉も、そちらに同じように用意します（私がやります）。RevenueCat には、本番用のWebhookを、もう1つ足します。
  • 審査に出す時は、サブスクを、アプリのバージョンに紐づけて、審査用のスクリーンショット（購入画面）を付けます（私が、手順を出します）。

この手順書は、docs/billing-setup.html です。チェックの印は、このブラウザに保存されます（消えても、困りません）。
