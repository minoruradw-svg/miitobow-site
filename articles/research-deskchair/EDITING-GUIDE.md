# 商品紹介記事の編集・レイアウトルール

更新日：2026-09-16
基準となる記事：`../research-deskchair.html`（この文書は research-deskchair フォルダに配置）

Claude Code等へ：この記事を編集するときは先にこの文書を読むこと。別の商品紹介記事へ展開する場合も構成の参考にできるが、商品数・商品名・仕様・評価・リンクをそのまま流用しない。ユーザーからの新しい明示指示を優先する。

## 1. 今回の編集意図と変更内容

「最初から調査報告を全部読む」必要をなくし、目的に合う商品へ早く進める構成にした。

- 長い導入4段落を短いリード文にまとめた。元の導入文は削除せず、後半の調査経緯へ移した。
- おすすめスライドの前に5つの目的別リンクを追加した。
- 商品を絞り込んだ調査経緯を後半の `details` に移し、必要な人だけ展開できるようにした。
- 通常の文章に入っていた細かな強制改行を除き、画面幅に合わせた自然な折り返しにした。
- 商品の事実・出典・Amazonリンク・スライド操作・商品テーマ見出しのモーションは維持した。

## 2. 文章の改行ルール（最重要）

### 通常の本文では、短い行にするための `<br>` を入れない

PC・スマホで画面幅が異なるため、10〜20文字ごと、文節ごと、句読点ごとの強制改行は禁止。本文の行長はCSSの幅で整え、ブラウザーに自然に折り返させる。

悪い例：
```html
<p>コーディングをしていると、<br>気づけば何時間も<br>同じ椅子に座っています。</p>
```

良い例：
```html
<p>コーディングをしていると、気づけば何時間も同じ椅子に座っています。</p>
```

同じルールを商品説明、仕様説明、レビュー紹介、画像の説明、PR表記にも適用する。ソースを読みやすくする目的でも、日本語の文節の途中に改行を入れると空白が表示されることがあるため、基本は1段落を1つの `<p>` として記述する。

### 話題が変わるときは `<p>` を分ける

1段落は1つの話題。目安は1〜3文だが、文字数で機械的に分割しない。段落間の余白はCSSで設定し、`<br><br>` や空の `<p>` で作らない。箇条書きは `ul` / `li` を使う。

```html
<p>耐荷重は、自分の体格に見合うかを確認します。</p>
<p>保証は年数だけでなく、対象となる部品も確認します。</p>
```

### 強制改行を残す例外

1. 商品のメインテーマ見出し：意味のまとまりとして意図した2行を残す。
```html
<h2 class="product-situation">とにかく安く、<br>長く使いたい人へ</h2>
```
2. FAQの質問と回答の境界：現在の構造では `Q.` と `A.` の間に1つの `<br>` を残す。回答本文は自然に折り返す。新規設計で質問・回答を別要素に分ける方法も可。
```html
<div class="faq-item"><p>Q. デスクチェアは組み立てが必要？<br>A. ほとんどの商品が、届いてから自分で組み立てる形式です。時間には余裕を持つのがおすすめです。</p></div>
```

**HTML全体から `<br>` を一括削除しない。** 見出しやFAQまで消すと意味の区切りが失われる。通常本文と例外を区別して編集する。

## 3. ページの構成

現在の順序を基本にする。

1. 記事一覧へのリンク、対象読者、短いテーマ見出し、比較の要約、目的別目次へのボタン
2. ワイドのオープニング画像、その直下にPR表記
3. 短いリード文、調査件数などのバッジ
4. 「目的から選ぶ」目次：商品ごとの紹介セクションへ直接移動
5. 「結論から先に言うと」おすすめスライド
6. 選び方の基準、比較表、比較内容のテキスト
7. 各商品のワイド紹介、向く人・向かない人、レビュー・仕様説明
8. 折りたたみの調査経緯
9. 調査での発見、迷ったときの選択、FAQ、関連記事、出典

長い調査経緯を再び冒頭に戻さない。読み飛ばして商品を選ぶ人と、根拠まで確認する人の両方に対応する。

## 4. 画像と文字の配置

- オープニング画像：画面幅いっぱい、縦横比を維持（`width:100%; height:auto`）。元画像の文字を切らない。
- PCの商品紹介：ワイドな面の左側にテーマ見出し・商品名・短い説明・Amazonボタン、右側に商品画像。
- 白背景の単体商品写真は `object-fit:contain` で商品全体を見せる。室内写真は構図に合わせて `cover` も使えるが、主役の商品を切らない。
- 背景と文字の間にグラデーションを入れて読みやすくする。写真の上に直接文字を載せて読みにくくしない。
- 700px以下：文章・ボタンを上、商品画像を下に分ける。PCの背景画像をそのまま狭い画面で切り抜かない。
- 向いている人／向いていない人は画像の下にカード。PCは2列、スマホは1列。
- 比較表の画像は中央寄せ。通常本文と比較表は最大720px、目次・スライドは最大1120pxを現在の目安とする。写真のワイド幅と本文の読みやすい幅を分ける。
- CSSの先頭には旧定義も残っている。末尾の上書き・メディアクエリを含めた最終適用値を確認する。

## 5. 見出し・操作・リンク

- 商品紹介の主見出しは商品名ではなく「誰に向くか」というテーマ。商品名はその次の階層。
- モーション対象は `.product-copy .product-situation` とトップの `.article-opening h1`。1文字ずつぼかしから現れ、表示後は止まる。画面外へ出てから再表示すると再生。本文や全見出しに広げない。
- `prefers-reduced-motion` を尊重する。
- おすすめスライドは手動切替。矢印・番号・スワイプ・キーボード操作を維持し、勝手に自動再生を加えない。
- 目次はPC5列、スマホ2列（最後は全幅）。各リンクはスライドではなく商品本体へ移動する。
- Amazonリンク、アフィリエイトタグ、PR表記、出典リンクを勝手に削除・置換しない。
- Pinterest等から直接移動できるため、既存の商品アンカーIDを変更しない。

## 6. 編集後の確認

- PC（例1440px）とスマホ（例390px）の実際の描画画像を見る。HTMLの確認だけで完了にしない。
- 横にはみ出さない、商品が切れない、文字が読める、画像が読み込めることを確認。
- 5つの目次リンク、スライドの矢印・番号、調査経緯の開閉を確認。
- 通常の段落に不要な強制改行がなく、テーマ見出しとFAQの必要な改行が残っていることを確認。
- 元の事実・注意点・出典・購入リンクが欠落していないか差分を確認。文章の整形と事実の更新を混同しない。
- 商品数や商品情報はその記事の根拠に合わせる。価格・保証・耐荷重などは未確認の数字で補わない。
- このルールを変更する依頼があった場合は、HTMLだけでなくこの文書も更新する。

## Claude Codeへの依頼文例

## 7. トップの編集（2026-09-16）

トップは「対象読者 → 短いテーマ見出し → 調査の要約 → 目的別目次へのボタン」の順。記事タイトルのtitle要素は検索向けの具体的な題名を維持する。H1は「長く座る毎日に、／自分に合う1脚を。」とし、意味の区切りのbrを例外として許可する。本文の要約にはbrを入れない。ボタンは #purpose-picks に移動。PRの説明は省略せず、ワイド画像の直下に配置する。画像内の既存タイトルとH1は異なる役割の文言にし、同じ見出しをそのまま繰り返さない。

## 8. 向く人・向かない人の下のまとめ帯（2026-09-16）

各商品の既存の結論文は、文言を維持したまま「選ぶ決め手」の小さなラベル付きで表示する。`.product-details .conclusion-line` を2枚のカード全体と同じ幅の淡いグリーンの帯にし、左に細い緑の線、内側に余白を設ける。ラベルは `.decision-label`、結論文は `.decision-text`。スマホでは縦に並んだカードの下に配置し、文章は強制改行せず自然に折り返す。濃色表示でも読める配色を維持する。全商品でこの表現を統一し、購入ボタンと紛らわしい見た目にはしない。

## 9. miitobow.comと配色を統一（2026-09-16）

基本背景は #F8F9FB、文字は温かい黒 #221F1B、補足は #6B6459。若草色 #6FAE2F を細い線などに使い、目次・決め手の帯は #F0F6E8。向いていない人・レビューは淡いベージュを使用する。購入ボタンとトップCTAは全箇所で #407F25＋白文字に統一する。公式サイトの #4C9A2A より少し濃くし、小さい白文字のコントラストを確保した。hoverは #32651D。配色はCSS末尾の --article-* 変数で管理し、ダーク表示の変数も確認する。写真上の白文字と暗いグラデーションは維持する。記事の配色変更では、写真そのもの・本文・リンク・モーションを変更しない。
